# GCalの認証情報保持 詳細設計

**前提:** `202610_GCalの認証情報保持_要件定義.md`（以下「要件定義」）の決定事項と構成の方針に従い、引数・戻り値・メソッドの中身を決める。節番号を「要件1.5節」のように書いたものは要件定義の節を指す。

**確認したライブラリのバージョン（`.venv`）:** `google-auth` 2.40.3 / `google-auth-oauthlib` 1.2.2 / `oauthlib` 3.3.1 / `google-api-python-client` 2.172.0 / `httplib2` 0.22.0 / `requests` 2.32.4。Python 3.9.13 で動くこと（`X | None` などの3.10以降の書き方は使わない）。

## 0. 要件定義との差分（確認してほしい点）
詳細を詰める中で、要件定義の記述と少し変えたい点・足したい点。問題なければ要件定義にも反映する。

| # | 内容 | 理由 |
|---|---|---|
| A | 起動時にトークンを更新（refresh）した後、ファイルに**保存し直さない**。要件5.2節の手順2「成功 → 保存し直して」を「成功 → 4へ」にする | 要件1.12節の理由（リフレッシュトークンは変わらず、次回また更新すればよい）が起動時にも当てはまる。毎朝の起動のたびにファイルを書かずに済む |
| B | 1分の時点でブラウザでの承認待ちではなく、まだ処理中（トークンの更新や初回の取得の通信が終わっていない）の場合、起動時の状態を `connecting`（接続中（つながると自動で連携します））とする | 要件6.1節の状態に「処理中」がない。「承認待ち」はブラウザが開いていないので合わず、「通信エラー」はその後に成功しても表示とずれるため |
| C | 起動時の状態に `invalid_token`（失敗（トークンが無効））を追加する | 認証の直後の取得で分類3が出る（更新できた直後にGoogle側で取り消された、403 `insufficientPermissions` など）と、要件6.1節のどの状態にも当てはまらない。まれだが、表示を間違えないため |
| D | 失敗の詳しいメッセージ（ポップアップ）は、起動時メッセージより**先に**出ることがある | Collectorは結果が出た時点で出し、起動時メッセージはVOICEVOXの起動・AI接続確認を待つため。順番をそろえるには `main.py` 側の作り込みが要り、要件4.1節の「Collectorの外への変更は最小限」に反するため、そろえない |

- A〜Dはすべて了承済みで、要件定義に反映した（A: 1.12節・5.2節、B: 1.3節・6.1節、C: 6.1節、D: 1.3節。2026-10-26）。

#### `_authenticate(debug=-1)`（要件5.2節）
```
二重開始の防止（既存の _auth_lock と in_progress の判定）
try:
    # 1. client_secret.json
    if not self._check_client_secret():
        self._handle_failure(StartupStatus.CLIENT_SECRET)
        return
    # 2. 保存済みのトークン（「毎回承認する」がオンなら __init__ で削除済みなので None になる）
    creds = self._load_token()
    if creds is not None and not creds.valid:
        creds = self._refresh_on_startup(creds)      # 分類3なら None、分類4ならそのまま返る
    # 3. ブラウザでの承認
    if creds is None:
        creds = self._run_browser_approval()
        if creds is None:
            return                                   # 分類2は _run_browser_approval の中で処理済み
        if not self._approve_every_start:
            self._save_token(creds)
    # 4. サービスの作成
    self.calendar_service = build("calendar", "v3", credentials=creds)
    self.tasks_service = build("tasks", "v1", credentials=creds)
    self.auth_state = "authenticated"
    # 5. すぐに1回取得する（要件1.3節）
    category = self._fetch_and_store(debug=debug)
    # 6. 起動時の状態
    status = StartupStatus.SUCCESS if category is None else category
    if not self._publish_startup_status(status) and status == StartupStatus.SUCCESS:
        logger.info("Googleカレンダーの連携に成功しました（起動時メッセージの表示後）。")   # 要件1.10節
except Exception as e:                               # 想定外のエラーは分類2（要件1.5節）
    logger.exception(...)                            # 3.3節の注意に従う
    self._handle_failure(StartupStatus.NOT_APPROVED)
```
- `_fetch_and_store()` の戻り値が分類3・5の場合のメッセージは、`_fetch_and_store()` の中で `_handle_failure()` を通して出す。ここでは起動時の状態に使うだけ。

#### `_check_client_secret() -> bool`
- ファイルがない → `False`。
- JSONとして読めない、または最上位に `"installed"` も `"web"` もない → `False`（`InstalledAppFlow.from_client_secrets_file` が `ValueError` を出す条件と同じ）。
- 失敗の理由（ない／形式が違う）は `logger.warning` に出す。ファイルの中身は出さない。

#### `_load_token() -> Optional[Credentials]`（要件2章「権限の不足の判定」）
```
if not os.path.exists(self.token_path): return None
try:
    info = json.load(...)
except (OSError, json.JSONDecodeError):  → logger.warning("読めない（分類3）"); return None
if not self._has_required_scopes(info.get("scopes")):
    logger.warning("使う権限が含まれていない（分類3）"); return None
try:
    return Credentials.from_authorized_user_info(info)    # scopes は渡さない（上書きされて不足を見落とすため）
except ValueError:                        → logger.warning("必要な項目がない（分類3）"); return None
```
- 分類3はログのみで、呼び出し元がブラウザでの承認に進む（要件5.2節）。ファイルは消さない（承認に成功すれば上書きされる）。

#### `_has_required_scopes(scopes) -> bool`（staticmethod）
- `scopes` が `str` ならスペースで分割、`list` ならそのまま、それ以外（`None` など）は空とみなす。
- `set(SCOPES) <= set(scopes)` を返す。余分な権限があっても `True`。

#### `_refresh_on_startup(creds) -> Optional[Credentials]`
```
try:
    creds.refresh(Request())                         # google.auth.transport.requests.Request
    return creds                                     # 保存し直さない（0章A）
except RefreshError as e:
    if self._classify_exception(e) == StartupStatus.INVALID_TOKEN:
        logger.warning("トークンが無効（分類3）。ブラウザでの承認に進みます。")
        return None
    logger.warning("トークンを更新できませんでした（分類4）。トークンを残して続けます。")
    return creds
except (TransportError, OSError) as e:
    logger.warning("通信エラー（分類4）…")
    return creds
```
- 分類4で返した `creds` は期限切れのままだが、次の取得でライブラリが更新を再試行する（要件1.12節）。

#### `_run_browser_approval() -> Optional[Credentials]`
```
flow = InstalledAppFlow.from_client_secrets_file(client_secret_path, SCOPES)
self._waiting_for_browser = True
try:
    creds = flow.run_local_server(port=0, access_type="offline", prompt="consent",
                                  timeout_seconds=APPROVAL_TIMEOUT_SECONDS)
except AccessDeniedError:      → 拒否。      _handle_failure(NOT_APPROVED); return None
except Warning:                → 一方だけ許可。_handle_failure(NOT_APPROVED, detail="partial"); return None
except AttributeError:         → タイムアウト。_handle_failure(NOT_APPROVED); return None
except Exception:              → 通信エラー・ポートが使えない等。logger.exception; _handle_failure(NOT_APPROVED); return None
finally:
    self._waiting_for_browser = False
if not self._has_required_scopes(creds.scopes):      # 念のための確認（OAUTHLIB_RELAX_TOKEN_SCOPE が設定されている環境など）
    _handle_failure(NOT_APPROVED, detail="partial"); return None
return creds
```
- `try` の範囲は `run_local_server` の1行だけにする（`AttributeError` を他の不具合と取り違えないため）。
- 一方だけ許可したとき、`oauthlib` は `OAUTHLIB_RELAX_TOKEN_SCOPE` が未設定なら `Warning` を投げる（`oauthlib/oauth2/rfc6749/parameters.py`）。`Warning` は `Exception` の派生なので、`except Exception` より前に置く。
- タイムアウトの `AttributeError` は、`run_local_server` の中で `wsgi_app.last_request_uri`（`None`）に `.replace` をかけて出る（`google_auth_oauthlib/flow.py`）。

#### `_save_token(creds)` / `_delete_token()`
- `_save_token`: `creds.to_json()` を `token_path + ".tmp"` に書いてから `os.replace`（`_write_cache()` と同じ方式）。`OSError` はログのみで続ける（要件1.11節）。`_approve_every_start` の判定は呼び出し元で行う。
- `_delete_token`: ファイルがあれば `os.remove`。`OSError` は `logger.warning` のみ。`.tmp` が残っていればそれも消す。

#### `refresh_cache(debug=-1)`（要件5.3節）
```
if not self.is_available(): return
self._fetch_and_store(debug=debug)
```

#### `_fetch_and_store(debug=-1) -> Optional[str]`
取得・キャッシュ書き込み・失敗の分類をまとめる。`refresh_cache()` と認証直後の取得の両方から呼ぶ。
```
failures: List[Tuple[str, str]] = []                # (サービス名 "calendar"/"tasks", 分類)
with self._fetch_lock:
    try:
        data = self._fetch_events_and_tasks(failures)
        self._write_cache(data)
    except Exception as e:                           # RefreshError・通信エラーなど、各 try で捕まえないもの
        category = self._classify_exception(e)
        if category is None:
            logger.error(...); return None
        failures.append(("", category))
# 分類の優先順位: 3 → 5 → 4
categories = {c for _, c in failures}
if StartupStatus.INVALID_TOKEN in categories:
    self._handle_failure(StartupStatus.INVALID_TOKEN); return StartupStatus.INVALID_TOKEN
if StartupStatus.API_DISABLED in categories:
    services = {s for s, c in failures if c == StartupStatus.API_DISABLED}
    self._handle_failure(StartupStatus.API_DISABLED, detail=services); return StartupStatus.API_DISABLED
if StartupStatus.NETWORK in categories:
    self._handle_failure(StartupStatus.NETWORK); return StartupStatus.NETWORK
return None
```
- 一部のカレンダーだけ失敗しても、取れた分でキャッシュを書く（現状どおり）。
- ロックは取得と書き込みの間だけ持ち、メッセージの発行は外で行う。

#### `_resolve_calendar_ids(failures)` / `_fetch_events_and_tasks(failures)`（変更）
- 今の `except HttpError as e:` の中に、`category = self._classify_http_error(e)` と、`category` があれば `failures.append(("calendar" or "tasks", category))` を足す。ログの出し方と、続けて取得する動き（`continue`・`primary` への切り替え）は変えない。
- `_resolve_calendar_ids` で Calendar API が無効だと、続く `events().list()` でも同じ分類が出るが、`_fetch_and_store` で1つにまとまる（要件10.3節）。

#### `_classify_exception(e) -> Optional[str]`（例外→分類を1か所にまとめる。要件8.1節）
| 例外 | 判定 | 分類 |
|---|---|---|
| `RefreshError` | `e.args[1]` が `dict` で、その `"error"` が `INVALID_TOKEN_ERROR_CODES` に含まれる | `INVALID_TOKEN` |
| `RefreshError` | 上記以外（5xx・コードが取れない） | `NETWORK` |
| `HttpError` | `_classify_http_error(e)` | |
| `TransportError`、`httplib2.HttpLib2Error`（`ServerNotFoundError` を含む）、`OSError`（`socket.timeout`・`ConnectionError` を含む） | | `NETWORK` |
| それ以外 | | `None`（ログのみ） |

- `RefreshError` は `google/oauth2/_client.py` の `_handle_error_response` で `RefreshError("<error>: <description>", response_data, retryable=...)` として作られるため、`e.args[1]` に応答のJSON（`dict`）が入る。`str` の応答のときは `args` が1つだけなので、`len(e.args) > 1` を確かめてから読む。

#### `_classify_http_error(e) -> Optional[str]` / `_extract_http_error_reasons(e) -> Set[str]`
- `_extract_http_error_reasons`: `e.content` を `json.loads`（`bytes` は `utf-8` で decode）し、`error.errors[].reason` と `error.details[].reason` を集める。JSONでない・形がちがう場合は空の集合。`HttpError.error_details`・`HttpError.reason` は使わない（要件10.3節）。
- `_classify_http_error`:

| 条件 | 分類 |
|---|---|
| `status_code == 403` かつ 理由が `API_DISABLED_REASONS` と重なる | `API_DISABLED` |
| `status_code in (403, 429)` かつ 理由が `RATE_LIMIT_REASONS` と重なる | `NETWORK` |
| `status_code == 403` かつ 理由が `INSUFFICIENT_SCOPE_REASONS` と重なる | `INVALID_TOKEN` |
| `status_code >= 500` | `NETWORK` |
| それ以外（403 `forbidden`・404 `notFound` など） | `None`（ログのみ） |

#### `_handle_failure(category, detail="")`（分類ごとの後始末と通知）
| 分類 | `auth_state` | メッセージ | 起動時の状態 |
|---|---|---|---|
| `CLIENT_SECRET` | `"failed"` | 出す | `_publish_startup_status(CLIENT_SECRET)` |
| `NOT_APPROVED` | `"failed"` | 出す（`detail == "partial"` で文言を変える） | `_publish_startup_status(NOT_APPROVED)` |
| `INVALID_TOKEN` | `"failed"`（以降の取得を止める。ブラウザは開かない） | 出す | 呼び出し元（`_authenticate`）が発行 |
| `API_DISABLED` | 変えない（取得は続ける） | 出す（`detail` のサービス名を入れる） | 呼び出し元が発行 |
| `NETWORK` | 変えない | 出さない（ログのみ。要件1.5節） | 呼び出し元が発行 |

- `CLIENT_SECRET`・`NOT_APPROVED` は `_authenticate` の途中で終わるため、ここで起動時の状態も発行する。

#### `_notify(category, message)`
```
if category in self._notified: return
self._notified.add(category)
self.bus.publish("Req_PopUpMessage", "warning", POPUP_TITLE, message)
```
- メッセージの種類はすべて `warning`（利用者に何かしてほしいが、アプリは動き続けるため）。

#### `_publish_startup_status(status) -> bool`
```
with self._status_lock:
    if self._startup_status_published: return False
    self._startup_status_published = True
if self._startup_timer is not None: self._startup_timer.cancel()
self.bus.publish("OnCalendarStartupStatus", status)
return True
```
- 結果とタイマーのどちらが先でも、ロックと旗で1回だけになる（要件10.2節）。`publish` はロックの外で呼ぶ。

#### `_on_startup_wait_timeout()`
```
status = StartupStatus.WAITING if self._waiting_for_browser else StartupStatus.CONNECTING   # 0章B
self._publish_startup_status(status)
```

### 1.7 メッセージの文言（`_handle_failure` が持つ）
| 分類 | 文言 |
|---|---|
| `CLIENT_SECRET` | client_secret.jsonが見つからないか、内容が正しくありません。<br>アプリと同じフォルダにclient_secret.jsonを配置し直して、アプリを終了して起動し直してください。 |
| `NOT_APPROVED` | Googleでの承認が完了しませんでした。<br>連携する場合は、アプリを終了して起動し直し、開いたブラウザの画面で5分以内に承認してください。 |
| `NOT_APPROVED`（一方だけ許可） | カレンダーとタスクの一方だけが許可されました。<br>アプリを終了して起動し直し、承認の画面で両方にチェックを入れてください。 |
| `INVALID_TOKEN` | Googleカレンダーとの連携が無効になりました（アクセスの取り消しなど）。<br>連携し直す場合は、アプリを終了して起動し直してください。起動時にブラウザでの承認に進みます。 |
| `API_DISABLED` | Googleカレンダーの予定を取得できませんでした。<br>GCPのプロジェクトで {Google Calendar API / Google Tasks API} が有効になっているか確認してください。 |

- トークンの中身・例外の詳細はメッセージに入れない（要件1.5節）。

## 6. 起動時の流れ（まとめ）

```
myapp.__init__
  GoogleCalendarCollector.__init__   キャッシュ削除 / 権限・ApproveEveryStart の写し取り / 必要ならトークン削除
  _setup_event_listeners             application start → start_TTS_Server, CalendarCollector.start
                                     subscribe_when(Start_TTS_Server, OnCalendarStartupStatus) → app_start_message
  publish("application start")
     ├─ [thread] start_TTS_Server → publish("Start_TTS_Server", engine_process)
     └─ [thread] CalendarCollector.start
            ├─ 権限OFF → publish("OnCalendarStartupStatus", "off")
            └─ Timer(60s) 開始 → _authenticate
                   ├─ client_secret NG → 分類1（メッセージ + 状態の発行）
                   ├─ トークン読み込み → 更新（分類3なら承認へ / 分類4なら残して続ける）
                   ├─ ブラウザでの承認（300s。失敗は分類2）→ 保存（ApproveEveryStart がオンなら保存しない）
                   ├─ build → auth_state = "authenticated"
                   ├─ _fetch_and_store（成功 / 3 / 5 / 4）
                   └─ 状態の発行（Timer が先なら発行済み。成功ならログのみ）
app_start_message(serverid, calendar_status) … 両方そろったら表示
```
