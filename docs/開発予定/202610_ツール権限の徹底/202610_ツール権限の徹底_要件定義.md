# ツール権限の徹底 要件定義

**対象:** DesktopCharacter / `ai_tools/tools_main.py`（`ToolExecutor`）, `ai/AI_main.py`（ReActのプロンプト）

# 概要
AIがReActで使うツールについて、権限設定 `ApplicationSettings.Permission.<ツール名>` がオフのものをAIに渡す一覧に含めないようにしたい。  
また、AIが一覧にないツール（存在しないツール、または権限がオフのツール）を呼ぼうとした場合は実行せず、「利用できない」と返すようにする。

> 2026-10-24、`202610_GCalの認証情報保持` の検討中にClaudeCodeとの確認で見つかった内容。カレンダー連携に限らずツール全般の話のため、別の要件定義として分けた。

---

## 1. 目的・スコープ

- 権限がオフのツールは、AIに一覧として見せない。
- 権限がオフのツールと存在しないツールは、AIが呼んでも**実行しない**。
- 権限の判定を `ToolExecutor` の1か所にまとめ、一覧・実行・ツール利用の例がすべて同じ判定結果を使うようにする。

### スコープ外
- 引数の検証（`execute_tool()` の `TODO: argsがargs_schemaに適合しているかバリデーション`）。
- 起動中の権限変更の即時反映（3.5節）。
- 権限がオンでも使える状態にないツールを一覧から外すこと（例: カレンダーが未認証）。ツールは中身を取得する部分（Collector）を参照できない作りのため。また未認証のときはツールが「未設定・未認証…」と返すので、AIはそれで判断できる。

---

## 2. 現状と問題点

権限がオフのツールを一覧から外す処理は、すでに `ToolExecutor.init_tools_descriptions()`（`ai_tools/tools_main.py:90`）にある。ただし外しているのは**説明文だけ**で、他の箇所では権限を見ていない。

| # | 場所 | 問題 |
|---|---|---|
| 1 | `ToolExecutor.execute_tool()`（`ai_tools/tools_main.py:110`） | 権限を見ていない。AIが一覧にないツール名を出力すると、権限がオフでもそのまま実行される |
| 2 | ツール利用の例（`ai/AI_main.py:428` の `tool_use_sample`） | 例に `get_active_window` / `get_current_time` / `get_playing_media` が固定で書かれている。これらがオフでも、AIが例をまねて呼ぶ可能性がある |
| 3 | `init_tools_descriptions()` で許可されたツールが0個のとき | 見出し「【利用可能なツール】」だけの文字列になる（「利用可能なツールはありません。」になるのは、ツールが1つも見つからなかったときだけ）。また、プロンプト側（`ai/AI_main.py:468`）にも同じ見出しがあり、二重になっている |
| 4 | debugモードの初期化（`ai_tools/tools_main.py:52-53`） | 権限に関係なく、すべてのツールを試しに実行している |

**1が最も重要な理由:**
- ツールの結果としてAIに渡る文字には、外部から来るものが含まれる（カレンダーの予定の説明欄、ウィンドウのタイトル、再生中の曲名など）。
- そこに「〇〇ツールを呼んで」と書かれていると、AIがそれに従って、オフにしてあるツールを呼ぶ可能性がある（プロンプトインジェクション）。
- 一覧から外すだけではAIの判断に任せることになるため、権限設定の守りとして足りない。実行する側で必ず止める必要がある。

---

## 3. 決定事項

### 3.1 権限の判定
- `ToolExecutor.__init__` で、見つかったツール（`self.tools`）のうち権限がオンのものを「許可されたツール」として1回だけ判定し、保持する（例: `self.allowed_tools`）。
- 判定の基準は現状と同じ。`ApplicationSettings.Permission.<tool.name>` が `True` のときだけ許可する。設定に項目がない場合や `True` 以外の値の場合は許可しない。
- 一覧（3.2節）・実行（3.3節）・ツール利用の例（3.4節）・debug時の試し実行（3.6節）は、すべてこの判定結果を使う。個別に権限を読み直さない。

### 3.2 AIに渡す一覧
- `init_tools_descriptions()` は、許可されたツールだけから説明文を作る（現状どおり）。
- 許可されたツールが0個の場合は「利用可能なツールはありません。」を返す（2章の問題3）。
- `init_tools_descriptions()` 側の見出し「【利用可能なツール】」は削除し、プロンプト側（`ai/AI_main.py:468`）の見出しだけにする。
- 権限がオフのツールは、名前も含めて一覧に一切出さない。

### 3.3 一覧にないツールが呼ばれたとき
`execute_tool()` の最初で判定し、許可されたツールでなければ**実行せず、エラー文を返す**。

| 呼ばれたツール | AIへの返答 | ログ |
|---|---|---|
| 存在しないツール | `エラー: ツール '<名前>' は利用できません。` | 「存在しないツールが呼ばれました」＋ツール名 |
| 存在するが権限がオフのツール | 同上（区別しない） | 「権限のないツールが呼ばれました」＋ツール名 |

- **黙って無視せず、「利用できない」と返す。** ReActのループは、ツールの結果を見て次の行動を決める。何も返さないと、AIは結果が来なかったと考えて同じツールを呼び直す可能性がある。「利用できない」と返せば、AIはそのツールを諦めて他の方法で応答できる。
- **AIへの返答では、存在しないツールと権限がオフのツールを区別しない。** 区別すると、オフにしてあるツールの存在をAIに（さらにプロンプトインジェクションを仕掛けた側に）知らせることになるため。原因の区別はログだけで行う。
- 現状の「存在しません」という文言は、上記の共通の文言に置き換える。
- エラー文を返したあとの流れは、現状の「存在しないツール」と同じ。結果に追加され（`ai/AI_main.py:503`）、ReActのループはそのまま続く。

### 3.4 ツール利用の例
- `ai/AI_main.py:428` の固定の例をやめ、許可されたツールの名前から作る（最大3個）。`ToolExecutor` に、許可されたツールの名前の一覧を返すメソッドを追加する（例: `get_allowed_tool_names()`）。
- 許可されたツールが0個の場合は、ツール利用の例をプロンプトに含めない。
- 例の `arguments` は `{}` のままでよい（現状の例も引数を書いていない）。

### 3.5 権限を反映するタイミング
- 起動時に1回だけ判定する。設定を保存しても、アプリを終了して起動し直すまで反映しない。
- 理由: `ToolExecutor` は現状でも起動時の設定を持ち続けており（`ai_tools/tools_main.py:44`。`AI_Manager.on_settings_updated()` は `ToolExecutor` を作り直さない）、動きは変わらない。また、カレンダー連携の「権限の変更は再起動後に反映」（`202610_GCalの認証情報保持_要件定義.md` 3.3節）ともそろう。
- 設定画面で、ツールの権限の変更には起動し直しが必要なことが分かるようにする。書き方は次のとおり（2026-10-24決定。カレンダー連携の要件定義もこれに合わせる）。
  - ツールの権限項目（`get_current_time` / `get_active_window` / `get_playing_media` / `get_user_activity_summary` / `get_calendar_info`）の説明文（`services/config_controller.py` の `description`）の末尾に、共通の一文「変更はアプリを終了して起動し直した後に反映されます。」を付ける。説明文がない項目には説明文を追加する。
  - ユーザー向けには「再起動」と書かない。右クリックメニューに再起動の項目がないため（カレンダー連携の要件定義 5.1節）。
  - 権限の欄（`ApplicationSettings.Permission` のセクション）にまとめて1つ書く方式は採らない。同じ欄の `ReAct_response`（`ai/AI_main.py:285`）と `UserActivityLog`（`main.py:229`）は保存した時点で反映されるため、欄全体に書くと誤った案内になる。
  - ツールを追加するときは、権限項目の説明文にこの一文を付ける。

### 3.6 debugモードの試し実行
- `ToolExecutor.__init__` の試し実行（`ai_tools/tools_main.py:52-53`）は、許可されたツールだけを対象にする。

## 5. 注意事項

- **`ai/new_AI_main.py`**: 同じ `ToolExecutor` を使っているが、どこからも import されていない（2026-10-24時点）。`ToolExecutor` 側の変更（3.1〜3.3節、3.6節）は自動的に効く。ツール利用の例（3.4節）は `ai/AI_main.py` だけを直す。`new_AI_main.py` を今後使う場合は、同じ対応が必要。
- **`ReAct_response` の権限**: `ApplicationSettings.Permission` には、ツールではない `ReAct_response`（ReActを使うかどうか）も並んでいる。3.1節の判定は「見つかったツールの名前」から設定を引くため、ツールでない項目が許可されたツールに混ざることはない。
- **ツールの説明文の中の、他のツールへの言及**: あるツールの説明文で別のツールの名前を挙げていると、そのツールがオフでもAIに名前が伝わる。現状のツールにそうした記述はないが、ツールを追加するときは避ける（呼ばれても3.3節で止まるため、問題になるのは見た目だけ）。
- **ログ**: 権限のないツールが呼ばれたときは、ツール名と引数をログに残す。プロンプトインジェクションを調べる手がかりになる。ただし、引数に個人情報が入る可能性があるため、ログに残すのはツール名だけにするかは設計方針で決める。

## 6. 確認項目
実装後に手動で確認する項目。結果は実装レポートに記録する。

| # | 確認内容 | 再現方法 | 期待する結果 |
|---|---|---|---|
| 1 | 一覧から外れる | 一部のツールの権限をオフにして起動し、debugモードでThoughtのプロンプトを確認する | オフのツールが「利用可能なツール」とツール利用の例のどちらにも出ない |
| 2 | 権限のないツールの実行を止める | 1の状態で、オフにしたツールを呼ぶよう会話で頼む（「〇〇ツールを使って」など） | ツールは実行されず、AIに「利用できません」が返る。ログに「権限のないツールが呼ばれました」が残る |
| 3 | 存在しないツール | 存在しないツール名を呼ぶよう会話で頼む | 2と同じ文言がAIに返る。ログに「存在しないツールが呼ばれました」が残る |
| 4 | 呼び直しが続かない | 2・3の後のAIの動きを確認する | 同じツールを何度も呼び続けず、他の方法で応答する |
| 5 | 全ツールがオフ | すべてのツールの権限をオフにして起動する | 「利用可能なツールはありません。」になり、ツール利用の例が出ない。会話は普通にできる |
| 6 | 再起動までの反映 | 起動中にツールの権限を変えて保存し、会話する。その後再起動して会話する | 保存しただけでは変わらず、再起動後に反映される |
| 7 | debugモード | debugモードで起動する | 権限がオンのツールだけが試し実行される |
| 8 | 許可されたツールは今までどおり | 権限がオンのツールを使う会話をする | 今までどおり実行され、結果が応答に反映される |
